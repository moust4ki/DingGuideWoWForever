# CLAUDE.md — notes for working sessions on Ding

Ding is a free leveling guide addon for **WoW Forever** (client 1.60.x, interface `16001`,
Lua 5.1), optimized for XP per hour and playable with a gamepad. The full specification is in
[`docs/SPEC.md`](docs/SPEC.md): read the part you touch before any change to the engine or to
the guide format (not the whole file).

The user (Yendi) plays **with a gamepad only**: every feature must be reachable through a
key binding (`Bindings.xml`) or Ding's chords, or happen by itself. Keyboard and mouse get an
equivalent for every gamepad action too.

## Map

Flow: a quest event -> `Engine:Update()` (delayed 0.2 s) -> `Advance()` passes the steps that
are done -> `Refresh()` computes the candidate points, then `Panel:Update()` and
`Arrow:Update()`; the arrow points to the nearest candidate and validates `go` steps.

```
Ding/Ding.toc, Bindings.xml   load order (optional: TomTom); every key binding
Ding/Core/      engine and logic: namespace, events and saved variables (Ding.lua), Compat (the
                API), Data (game data), Registry (packs), Engine, Travel, AutoQuest, Goals,
                Grind, Why, Import / GuideText (guides as text), Commands (/ding)...
Ding/UI/        Ding's own frames: Themes, Widgets (tokens, shapes, fonts), Gamepad, Panel (guide
                window), Arrow, Config (settings), Setup (assistant), Finder (NPC directory)...
Ding/Locales/   interface texts (enUS.lua + one file per language); Guides/<locale>/: guide
                translations
Ding/DB/        DingDB, the game database, generated by tools/build_data.lua (never by hand)
Ding/Guides/    the packs: Leveling (generated by tools/write_leveling.lua), Zones, Items, Class,
                Dungeons (drafted by tools/draft_dungeon.lua, finished by hand)
Ding/Media/     kit textures (white, tinted) and the icon; Noto Sans fonts (OFL)
examples/       DingExamplePack: example guide pack (separate addon, not in the zip), tested
tools/          offline Lua 5.1 scripts: checks, tests (tests/*_test.lua), wow_mock.lua (mocked
                WoW API), route writers, data builder
docs/           SPEC, architecture, UI handoff and themes, public contracts (guide-packs,
                dingdb, create-a-guide-with-ai), compatibility
```

Details: [`docs/architecture.md`](docs/architecture.md) (every file, the contracts between
modules, `Ding.db` / `Ding.char`).

## Hard rules

Product:

- **Plain words**: the player understands everything in words; no meaning carried only by a
  color, an icon or developer shorthand; the guide says why it makes its choices (SPEC, Plain
  words; `Core/Why.lua`). Lists cut short say "and 2 more" (`UI.More`), never "+2".
- **Gamepad**: never a button captured for good on a shown window. Commands go through key
  bindings or Ding's chords (`Ding.db.chords`); navigation in a window through temporary
  bindings that only take the useful keys, read first by `DingPadInput` while it is open.
- **Keyboard and mouse**: click = A, right-click = Y or cancel, Escape = B, clickable buttons in
  move mode; without an active gamepad (`Gamepad:Active`) the help and messages speak of the
  mouse and the keyboard (`mouse_test`, SPEC §3).
- **Each action shows once**: a button carries its chips (`UI.ButtonKeys`: A on the focused
  one, B on the one that closes); a hint bar only lists what no button on screen does
  (`single_action_test`, every window, with and without a gamepad, every language).
- Guides: an optional step must never block; a step behind an option disappears whole when it
  is off; every module asks `Ding:StepApplies(step)`. Keys: SPEC §2.
- `docs/guide-packs.md` and `docs/dingdb.md` are public contracts: a guide or step key or a
  behavior they describe changes together with them, `examples/`, the import's whitelists
  (`Import.STEP_KEYS`, `GUIDE_KEYS`, `PACK_KEYS`) and `docs/create-a-guide-with-ai.md`.

Code:

- Lua 5.1: no `goto`, no bitwise operators (race masks go beyond 32 bits: `math.floor(mask /
  bit) % 2`), global `unpack`, `#` only on sequences without holes.
- Every module: `local _, Ding = ...` then a local table exposed on `Ding`.
- Forever API: prefer `C_*`, go through `Ding.Compat`, `pcall` any doubtful function. Every
  number or boolean from the API goes through `Compat.Plain` (**secret values** = nil). Never
  `GetUnitSpeed`. Client formats are positional (`%1$s`) with `|4singular:plural;`.
- Every display called by the engine or a timer goes through `Ding:Safe(fn, ...)`.
- **Never drive a game window from Ding** (quest log, map, options, `ShowUIPanel`,
  `HideUIPanel`…): taint (`taint_test`). Ding shows what is needed in its own frames.
- **Never take the keyboard from a box Ding does not own** (`EditBox:SetFocus` while the chat
  has it): `ImportWindow:Focus` waits until `GetCurrentKeyBoardFocus()` is free.
- Temporary bindings (`SetOverrideBindingClick`) only out of combat, removed on
  `PLAYER_REGEN_DISABLED`.
- Interface: `docs/UI-handoff.md` and `docs/UI-themes.md` to the pixel. **Every paint goes
  through a `UI.C` token** and the painting helpers (no color literal in `Ding/UI` but
  `UI/Themes.lua`: `themes_test`; a theme never holds a size, a padding nor a font size); fonts
  through `UI.Font` (Noto Sans; the game's font for Korean and Chinese), shapes through
  `UI.Shape` / `UI.Window`, focus through `UI.Focus`, gamepad buttons through `UI.Glyph`. Never
  BackdropTemplate nor a WoW window texture (`look_test`). **No arrows nor shapes in texts**
  (← → ◂ ▸ ✕ □ △ ○…): they are textures. No Ace3, no XML templates, no protected frame except
  `DingItemButton` (attributes, showing and position only out of combat, anchored to UIParent).
- Anchors: stretch with `TOPLEFT`/`TOPRIGHT` pairs, never `TOPLEFT` + `RIGHT` (smoke test).
- Game data only through `Core/Data.lua` (a missing number is `0`; `startedBy`, `finishedBy`,
  `objectives` always a table; other empty tables `nil`). Fixes go in
  `tools/data/corrections/*.lua`, never in `Ding/DB`.

Language and names:

- **Everything in English**: code, comments, docs, tests, tool output, commit messages, pull
  requests. French only where it is data: translations (`Ding/Locales/frFR.lua`,
  `Ding/Locales/Guides/frFR/`, `tools/routes/locales/frFR.lua`, examples' `Locales/frFR.lua`),
  localized TOC fields (`## Notes-frFR`), French texts a test expects from the mocked client.
- The name players see is **Ding!** (`Ding.TITLE`, every interface text and pack name, every
  language); code, folder, saved variables, `/ding` and `## Dependencies: Ding` keep "Ding".
- Interface texts through `Ding.L`: a key goes in `Locales/enUS.lua` **and** every
  `Locales/<locale>.lua` (frFR, deDE, esES (also esMX), ptBR, koKR, zhCN, zhTW; `locales_test`
  checks keys and `%d`/`%s`). Guide texts in English; their translations in
  `tools/routes/locales/<locale>.lua`, written out by `tools/translate_guides.lua` (SPEC §2).

Licenses:

- `Ding/DB` is built from Questie's GPL database and keeps its credits (`Ding/DB/CREDITS.md`,
  the README, each generated file's header). Guides only hold quest ids, route coordinates and

- TomTom is "all rights reserved": only its public API (`Ding.TomTom`), always `pcall`, no file

- Noto Sans (OFL 1.1) ships with its license.

## Checking a change

Nothing runs in the game here: the checks are the only safety net. Lua:
`D:/Dev/QuestieDB/tools/lua-binary/lua.exe` (or `lua5.1`); `$QDB` = the QuestieDB v1.0.6
Forever export (`../QuestieDB/src/corrections/Forever/combined`, tools/README.md section 1).

- **While working**, only what you touch:
  `lua5.1 tools/run_tests.lua $QDB <name part>`, `lua5.1 tools/check_guides.lua $QDB` after a
  guide change, one `lua5.1 tools/smoke_test.lua $QDB --quiet`.
- **Once before pushing**, the whole suite in parallel: `bash tools/check_all.sh` (env `LUA`,
  `QDB`, `JOBS`; prints `ALL GREEN` or `FAILURES`).
- A new WoW function used by the addon goes in `tools/wow_mock.lua`. Every feature comes with
  its unit tests and its smoke test scenario. CI (`.github/workflows/tests.yml`) runs it all on
  every PR.
- Small commits, one per task, messages in English.

Details: [`tools/README.md`](tools/README.md) (section 9: every command; section 1: the export;
sections 6-8: routes and guides).

## Publishing

CurseForge project `ding-xp-and-leveling-guide` (id 1739053). A `v*` tag starts `release.yml`
(suite, BigWigs packager, `tools/check_package.py`, CurseForge + GitHub). Before each tag, add
the version's entry at the top of `CHANGELOG.md` (players read it). **Never push a tag without
Yendi's agreement.** `.pkgmeta` keeps `tools`, `docs`, `examples`, `README.md` and `CLAUDE.md`
out of the zip.

Details: [`tools/README.md`](tools/README.md) (section 10: the release, what only the game can
validate).
